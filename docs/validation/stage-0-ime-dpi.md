# 阶段 0 输入法、高 DPI 与主题验证

验证时间：2026-08-07（Windows 11 / WebView2）

## 自动化结果

- 1440 × 900：三栏均可见，主工作区、检查器和底部状态栏无横向溢出。
- 1024 × 720：左栏收为图标栏，右侧检查器保留；文档宽度与视口宽度同为 1024 CSS px，无横向滚动。
- 中文与标点文本可写入验证区，字符计数按 Unicode 字符更新，`input` 事件进入组合事件日志。
- “跟随系统 / 亮色 / 暗色”均可切换；暗色模式的选中态和根节点主题属性同步。
- 主题控件、文本区和主要导航具备可见键盘焦点样式。
- 浏览器控制台在装载、切换主题、输入和响应式检查后均为 0 error / 0 warning。
- 当前验证页会实时显示 `devicePixelRatio`、视口尺寸、屏幕逻辑分辨率和根字号；浏览器默认环境曾读取到系统 DPR 1.50，显式 1440 × 900 测试视口使用 DPR 1.00。
- release 性能采样连续 5 次收到 Svelte 调用 Rust `frontend_ready` 后生成的标记，证明打包应用内最小 IPC 链路可用。

## 人工验收入口

运行 `npm run tauri dev` 或 release 可执行文件，在“输入与缩放检查”页完成：

1. 用微软拼音或常用中文输入法输入候选词，确认 `compositionstart`、`compositionupdate`、`compositionend`、`input` 顺序和数据合理。
2. 检查候选窗不被遮挡，回车换行、逗号句号、退格删除均正常。
3. 在 Windows 100%、125%、150%、200% 缩放下重启应用，确认文字与分隔线清晰、三栏可用、标尺仍代表 100 CSS px。
4. 修改系统明暗主题，确认“跟随系统”状态下即时同步；再确认手动亮色或暗色不会被系统变化覆盖。

自动化 `fill` 不会打开 Windows 输入法候选窗，也不能替代真实 IME 组合过程；切换系统缩放还会影响当前桌面会话。因此这两项保留为不会扰动用户系统设置的人工验收步骤，验证页已提供全部观察点。
